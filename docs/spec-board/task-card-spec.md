# spec-board - タスクカード仕様（フロントエンド）

> **機能**: [spec-board](./index.md)
> **ステータス**: 下書き

## 概要

ボード上の各タスクを表すカード型UI要素の表示仕様、詳細（全画面 2 ペイン）、およびタスク作成・編集フォームを定義する。

## コンポーネント

| コンポーネント | 種別 | 説明 | 振る舞い |
|:-------------|:-----|:-----|:---------|
| タスクカード | カード | タイトル・優先度・ラベル・サブIssue進捗を表示する小型カード | ドラッグ可能。クリックで詳細（全画面 2 ペイン）を開く |
| 詳細（全画面 2 ペイン） | 全画面ビュー | タスクの全情報を表示・編集できる全画面 2 ペイン（左＝タイトル＋本文 / 右＝プロパティサイドバー） | カードクリック（または Enter / Space）で `detail` 区分へ遷移 |
| タスク作成フォーム | モーダル | 新規タスクの入力フォーム | カラムの「+ 追加」ボタンから開く |
| 優先度バッジ | バッジ | 優先度を色で示す小型ラベル | High: 赤、Medium: 黄、Low: 青。未設定時はバッジ非表示 |
| 期限バッジ | バッジ | 期限を今日基準の相対表現で示す小型ラベル | 「今日」/「あと X 日」/「X 日超過（期限切れ）」。期限切れは赤系で強調。未設定・空文字・不正フォーマット時はバッジ非表示 |
| ラベルタグ | タグ | カテゴリやカスタムラベルを示すタグ | prefix（`type:`/`priority:`/`area:`/`status:` 等）でグループ分類し、グループ単位で固定色を適用。prefix 無しは default 群の色。詳細は [label-registry-spec.md](./label-registry-spec.md) |
| サブIssue進捗バー | プログレスバー | 全子孫タスクの完了状況を示す水平バー | 完了数/全数を色で示す。子孫タスクが 0 件の場合は非表示 |
| サブIssueリスト | リスト | 直接の子タスクのタイトルとステータスの一覧 | カードに折りたたみ表示。クリックで子タスクの詳細へ切替 |
| リンクリスト | リスト | 関連タスクのタイトルとステータスの一覧 | 詳細（全画面 2 ペイン）に表示。クリックで遷移 |

## タスクカード表示

### カードレイアウト

```
┌──────────────────────┐
│ [優先度] タイトル      │
│                      │
│ [ラベル1][ラベル2]     │
│                      │
│ ▶ サブIssue          │
│  ├ ✓ 子タスク1        │
│  ├ ○ 子タスク2        │
│  └ ...               │
│ [████████░░]         │
│ task-123  🔗 2  2/5  │
└──────────────────────┘
```

- タスクカードでは、子孫タスクが 1 件も無い場合は `<details>` セクション全体（サマリ表記・直下子リスト・進捗バー）を非表示にする
- サブIssueリストはデフォルト折りたたみ。▶ クリックで展開/折りたたみ
- リスト展開時は直接の子タスクのみ表示（孫タスクは子タスクの詳細で確認）
- 進捗バーは**全子孫**を対象に集計する:
  - 総数 = 全子孫タスクの件数（直下子だけでなく孫・曾孫…も含む）
  - 完了数 = 総数のうちステータスが「完了カラム」と一致するものの件数
  - サイクル参照（A→B→A、A→A）が存在しても有限ステップで停止し、同一子孫は 1 回だけ数える
- **進捗バーは X/Y 数値を視覚表記しない**（バーのみ表示）。X/Y 数値はカードフッターへ集約して重複を排除する。進捗値はバー（`progressbar`）の `aria-label="進捗 X/Y"` / `aria-valuenow` でスクリーンリーダーへ提供する

#### カードフッター

カード下端に以下を 1 行で表示する。各要素はゼロ抑制し、全要素が非表示でも ID のみの最小フッターになる。

| 要素 | ソース | 表示条件 |
|:----|:-------|:--------|
| タスク ID | `task.id` | 常時表示（長い ID は `truncate` で省略） |
| リンク件数 | `task.links.linkedFilePaths.length`（forward links の件数） | 1 件以上のとき `🔗 N` を表示。0 件は非表示 |
| サブIssue X/Y | 全子孫の完了数 / 総数（進捗バーと同一の集計源 `countSubIssueProgress`） | 総数が 1 件以上のとき `X/Y` を表示。0 件は非表示 |
- 詳細（DetailScreen 内 SubIssueSection）では「+ サブIssue 追加」ボタンは常時表示し、進捗バーと直下子リストはそれぞれ独立条件で表示する:
  - 進捗バー: 全子孫が 1 件以上のとき表示
  - 直下子リスト: 直下子が 1 件以上のとき表示（子孫が 0 件で進捗バーが消えても直下子リストは残る、ただし両者が同期する一般的な production データではこの分岐は出ない）

### 表示データ

| フィールド | ソース | フォーマット | 空の場合 |
|:----------|:-------|:------------|:---------|
| タイトル | フロントマター `title` | そのまま表示 | ファイル名を表示 |
| 優先度 | フロントマター `priority` | バッジとして表示（High/Medium/Low） | バッジ非表示 |
| 期限 | フロントマター `due` | バッジとして相対表示（今日基準） | バッジ非表示 |
| ラベル | フロントマター `labels` | タグとして横並びに表示 | タグ非表示 |
| サブIssue進捗 | 全子孫タスク（再帰展開）の `status` を集計 | プログレスバーのみ（X/Y 数値はフッターへ集約。進捗は `aria-label`/`aria-valuenow` で保持） | 子孫 0 件で非表示 |
| サブIssueリスト | 直接の子タスクの `title` と `status`（孫以下は含まない） | チェックアイコン付きリスト | 直下子 0 件でリストのみ非表示 |
| タスク ID | `task.id` | フッターに常時表示（長 ID は truncate） | - |
| リンク件数 | `task.links.linkedFilePaths.length` | フッターに `🔗 N` | 0 件で非表示 |
| 本文タスクリスト進捗 | 詳細（DetailScreen）の本文中のタスクリストブロックの checkbox 完了率（checked 数 / checkbox 総数）。**子タスク status を集計するサブIssue進捗とは別概念**で、本文内のチェックボックスのみを対象にブロックごとに集計する | 該当タスクリストブロック直上にプログレスバー + 「完了数/全数」 | checkbox 0 件のブロックでは非表示 |

### 下書き（draft）タスクの表示

- frontmatter に `draft: true` を持つタスクは、カンバンボードの TaskCard を**グレー表示（減光）+ タイトル行に「下書き」バッジ**で表示する。カード自体は非表示にしない。
- ドラッグ中の減光（dragging 側の opacity）と draft の減光は重複適用せず、ドラッグ中は dragging 側を優先する。
- 詳細画面（DetailScreen）では「下書き」バッジと「下書きを解除」UI を表示し、解除操作で `update_task { draft: false }` を発行して frontmatter から `draft` キーを除去する。
- draft 表示の適用対象は**カンバンボードの TaskCard と詳細画面のみ**とする（ListView / TreeView 等の他ビューへの draft 表示は本仕様のスコープ外。必要になった時点で後続 Issue で扱う）。

### 期限（due）の相対表示

- カードおよび詳細（全画面 2 ペイン）に期限バッジを表示する。`due` 未設定・空文字・取得できない場合はバッジ非表示。
- 今日を基準に以下の相対表現で表示する（today はクライアントのローカル日付。日付差は UTC で算出する）。
  - 期限当日: 「今日」
  - 未来: 「あと X 日」
  - 過去: 「X 日超過（期限切れ）」— 視覚的に強調（赤系背景）する。
- 不正フォーマット（`invalidDue` warning 付き）はバッジを表示しない。`invalidDue` は Task の warnings payload には含まれるが、本仕様では UI 表示対象外とする（parse-error バナー・カードのエラーアイコン・専用 warning 表示のいずれにも出さない）。

## 詳細（全画面 2 ペイン）

### レイアウト

```
┌────────────────────────────┐
│ 親: 親タスク名          [×] │
│ タイトル（編集可能）         │
│                            │
│ ステータス: [Todo ▼]        │
│ 優先度:    [Medium ▼]      │
│ ラベル:    [ラベル1][+追加]  │
│                            │
│ ──── サブIssue (2/5) ──── │
│ [████████░░]               │
│  ✓ 子タスク1    Done       │
│  ○ 子タスク2    Todo       │
│  ○ 子タスク3    In Progress│
│          [+ サブIssue追加]  │
│  ※ 「2/5」のサマリとバーは全子孫を対象に集計する │
│  ※ リストは直下子のみを表示する（孫タスクは含めない） │
│                            │
│ ──── 関連タスク ────────── │
│  ○ 関連タスク1   Todo  [×] │
│  ○ 関連タスク2   Done  [×] │
│          [+ リンク追加]     │
│                            │
│ ──────────────────────     │
│                            │
│ 説明（Markdown 表示 / クリックで編集）│
│ ここにmdファイルの本文を     │
│ レンダリングして表示する      │
│                            │
│ ──────────────────────     │
│ ファイルパス: tasks/xxx.md  │
│                            │
│        [削除]              │
└────────────────────────────┘
```

### ユーザー操作

| 操作 | トリガー | 振る舞い | 遷移先 |
|:-----|:--------|:---------|:-------|
| 詳細を開く | タスクカードをクリック（または Enter / Space） | 全画面 2 ペイン詳細（DetailScreen）へ遷移 | - |
| 詳細から戻る | 「← 戻る」ボタンクリック / Escキー | board へ戻り選択を解除する（削除確認ダイアログ・作成モーダル表示中の Esc は抑止） | board |
| タイトル編集 | タイトル部分をクリック | インライン編集モードに切り替え。Enterで確定、Escでキャンセル。確定時にmdファイルを更新 | - |
| ステータス変更 | ドロップダウン選択 | フロントマターの `status` を更新し、ボード上のカードも移動 | - |
| 優先度変更 | ドロップダウン選択 | フロントマターの `priority` を更新 | - |
| ラベル追加 | 「+ 追加」ボタンクリック | ラベル入力フィールドを表示。入力確定でフロントマターの `labels` に追加。追加は楽観的に DetailScreen 表示へ即時反映され、`update_task` IPC の応答を待たずに UI が更新される。IPC が失敗した場合は元の labels 配列にロールバックし、画面右上のトーストでエラーを通知する。成功した場合も成功トーストを 1 件表示する | - |
| ラベル削除 | ラベルタグの×ボタンクリック | フロントマターの `labels` から削除。削除も楽観的に DetailScreen 表示へ即時反映され、`update_task` IPC の応答を待たずに UI が更新される。IPC が失敗した場合は元の labels 配列にロールバックし、画面右上のトーストでエラーを通知する。成功した場合も成功トーストを 1 件表示する | - |
| 本文編集 | 本文（説明）領域をクリック / Enter / Space | textarea に切替えて編集モードに入る。`Cmd/Ctrl + Enter` で確定し `update_task` IPC で永続化、`Esc` でキャンセル。確定/キャンセルとも detail は閉じず board へは戻らない。空 body 保存可。未変更（strict equality）の Cmd/Ctrl+Enter は IPC を呼ばずに display に戻る（先頭/末尾の空白差分は変更として扱う）。IME 変換中の Cmd/Ctrl+Enter は誤確定しない。編集は楽観的に DetailScreen 表示へ即時反映され、IPC が失敗した場合は元の body にロールバックし error toast を表示。成功時も success toast を 1 件表示する | - |
| 本文タスクリスト toggle | 本文中の `- [ ]` / `- [x]` チェックボックスをクリック | 該当**1 行のみ** `[ ]`↔`[x]` を書き換えて `update_task` IPC で永続化する。本文編集と同じく楽観反映 + 失敗ロールバック + success/error toast に乗る。チェックボックスのクリックは本文編集（textarea）モードへは遷移せず、本文編集モード中はチェックボックスを非インタラクティブにする。同一文言の他行・空白・改行・未対応記法は不変。Raw 表示のトグル UI は提供しない（未対応記法は生表示） | - |
| 親タスクへ遷移 | ヘッダーの「`親: {親タスクタイトル}`」リンクをクリック / キーボード操作（Enter / Space） | 親タスクの詳細に切り替え。親が無い場合・孤児参照・コールバック未指定時はリンク自体を描画しない。親タイトルが空のときは親の filePath を fallback として表示 | 親タスクの詳細 |
| サブIssue追加 | 「+ サブIssue追加」ボタンクリック | タスク作成フォームを開く（`parent` に現在のタスクを自動設定） | - |
| サブIssueへ遷移 | サブIssueリストの項目クリック | detail は閉じず、同じ画面内で表示対象 task を子に差し替える。<br>切替時に `LiveRegion`（aria-live=polite）で `「{title}」を表示中` を読み上げる。<br>親タスクへの遷移（ヘッダーの ParentLink）も同じ文言でアナウンスする。<br>編集中の MarkdownBody（未保存テキスト）は名前空間付き key（`title-${task.id}` / `body-${task.id}`）による再マウントで破棄される（タイトルと本文が兄弟要素のため key 衝突を避ける）。<br>履歴スタックは持たないため、戻りたい場合は ParentLink を使う | 子タスクの詳細 |
| リンク追加 | 「+ リンク追加」ボタンクリック | タスク検索・選択UIを表示。選択したタスクのパスをフロントマターの `links` に追加 | - |
| リンク削除 | forward (linked) 行末尾の × ボタンクリック（aria-label="リンクを削除"、確認ダイアログなし） | フロントマターの `links` から該当パスを削除。削除は楽観的に DetailScreen 表示へ即時反映され、`remove_link` IPC の応答を待たずに UI から該当 `<li>` が消える。IPC の source=自分 / target=相手で発行する（md を書き換える側を常に source とする契約）。IPC が失敗した場合は元の links 配列にロールバックし、画面右上のトーストでエラーを通知。成否いずれも aria-live で「{source-title} から {target-title} へのリンクを削除しました」（成功）/「…のリンク削除を取り消しました」（失敗）の文面で読み上げ。busy 中はセクション内のすべての × ボタンと「+ リンク追加」ボタンが disabled になる。reverse 行は読み取り専用で × ボタンを持たず、削除したい場合はリンク元のタスクを開いて forward 側から削除する | - |
| リンク先へ遷移 | 関連タスクセクションの links / reverseLinks 行クリック | detail を閉じずに同じ画面内で表示対象 task を切り替える（in-place 切替）。links → reverseLinks の順で表示し、それぞれの行が button としてフォーカス可能。切替時に `LiveRegion` で `「{title || filePath}」を表示中` を読み上げる。target が tasks に存在しない場合（壊れたリンク）はクリックを完全 no-op（selectedTaskId 不変、announce なし、追加 UI フィードバックなし）。自タスクを指すリンク（自己リンク）クリックは画面遷移が起きず、LiveRegion のみ同じ文言で再アナウンスする。`onSelectTask`（コールバック）未指定時は行 button が disabled になる | リンク先タスクの詳細 |
| タスク削除 | 「削除」ボタンクリック | 確認ダイアログ表示後、`delete_task` IPC を発行。子タスクがある場合は確認ダイアログ内のラジオで `clear`（子の `parent` を解除して削除）/ `abort`（削除中止）を選択する。確定時点でボード上のカードを楽観的に消し、DetailScreen は削除直前の snapshot を fallback として描画継続する。成功時は board へ戻し、`タスクを削除しました` トーストを表示しつつ live-region に `「{title}」を削除しました` をアナウンスする（タイトル付き文言は SR 向け）。失敗時はカードを snapshot 全体から復元し、detail に留まったまま `タスクの削除に失敗しました: {message}` トーストと `「{title}」の削除を取り消しました` アナウンスを発火する（確認ダイアログは error 状態で維持され、リトライ可能） | 成功時は board へ戻る / 失敗時は detail 維持 |

## タスク作成フォーム

### フィールド定義

| フィールド | 種別 | 必須 | 初期値 | 説明 |
|:----------|:-----|:-----|:-------|:-----|
| タイトル | テキスト | はい | 空 | タスクのタイトル。ファイル名の自動生成元（kebab-case変換） |
| ファイル名 | テキスト（`.md` 固定サフィックス表示） | いいえ | タイトルから自動生成 | 手動編集で自動追従停止・空クリアで再開。重複時は保存時に連番付与（submit はブロックしない）。入力値のまま表示し、連番回避後の確定名プレビューは行わない |
| ステータス | セレクト | はい | 作成元カラムのステータス | タスクのステータス |
| 期限 | ネイティブ date 入力 | いいえ | 未設定 | `YYYY-MM-DD`。未入力時は frontmatter に `due` キーを出力しない |
| 優先度 | セレクト | いいえ | なし | High / Medium / Low / なし。「なし」選択時はフロントマターに `priority` を出力しない |
| ラベル | タグ入力 | いいえ | 空 | カンマ区切りで複数入力可能 |
| 親タスク | タスク選択 | いいえ | なし（サブIssue追加時は自動設定） | 親タスクを検索・選択。既存タスクから選択 |
| 説明 | テキストエリア | いいえ | 空 | タスクの詳細説明（Markdown） |
| サブIssue | 複数行テキスト | いいえ | 空 | 1 行 = 1 サブIssue。空行は無視。保存時に親と同時作成され、部分失敗は親と成功した子を残して警告トーストを表示（ロールバックしない） |
| 下書き | チェックボックス | いいえ | OFF | ON で frontmatter に `draft: true` を出力 |

### バリデーションルール

| フィールド | ルール | エラーメッセージ | タイミング |
|:----------|:------|:---------------|:----------|
| タイトル | 空文字不可 | タイトルを入力してください | onSubmit |
| ファイル名 | OS 予約文字（`< > : " / \ \| ? *`）を含まない | ファイル名に使用できない文字が含まれています | onSubmit |
| サブIssue | 各行にタイトルと同じ検証（予約文字・文字数上限）を適用 | 行番号付きでタイトルと同じ文言を表示 | onSubmit |

- **タイトル / ファイル名の重複は submit をブロックしない**（「同じタイトルのタスクが既に存在します」エラーは撤回）。既存ファイル名と重複する場合は保存時に BE が連番サフィックスを付与して回避する。

### 送信時の動作

| アクション | 処理 | 成功時 | 失敗時 |
|:----------|:-----|:-------|:-------|
| タスク作成 | フロントマター付きmdファイルを作成 | モーダルを閉じ、ボードに新カードを表示 | トースト通知でエラーメッセージ表示 |
| サブIssue 同時作成 | 親の作成成功後、サブIssue 各行を 1 件ずつ直列に `create_task`（`parent` = 親の確定パス、`status` / 下書きは親フォームの値を引き継ぐ） | 全件成功で成功トーストを表示し画面を閉じる | 親の作成失敗時は子を作成せず画面を維持。子の部分失敗時は親と成功した子を残し「サブIssue N 件の作成に失敗しました」警告トーストを表示して画面を閉じる（ロールバックしない） |

## エラー表示

| エラーケース | 発生条件 | 表示方法 | ユーザーアクション |
|:------------|:---------|:---------|:----------------|
| ファイル保存失敗 | ディスク容量不足、権限エラー | トースト通知 | ファイルシステムの状態を確認 |
| ファイル削除失敗 | ファイルが既に削除されている、権限エラー | トースト通知 | ボードをリロード |
| フロントマターパースエラー | mdファイルのフロントマターに invalid 系の値が含まれる（対象 warning code: `invalidTitleUsedFileName` / `invalidStatusUsedDefault` / `invalidParentIgnored` / `nonStringExtraKeyIgnored` / `extraValueNotJsonCompatible`） | 詳細（全画面 2 ペイン）: 赤系エラーバナー（`role="alert"`、dismiss 不可、固定文言「フロントマターに不正な値があります。md ファイルを手動修正してください。」。複数 invalid があっても件数・個別 message は列挙しない）を表示。タスクカード: タイトル行右端に赤いパースエラーアイコンを表示（リンク切れの黄アイコンと併存可） | mdファイルを手動修正 |
| リンク切れ | `parent` / `links` / `children` / `reverseLinks` のいずれかで指定された参照先タスクが一覧に存在しない | 詳細（全画面 2 ペイン）: 該当行に警告アイコン + 「リンク切れ」テキスト + 取消線スタイル付き path 表示。タスクカード: 1 件でもリンク切れがあるカードはタイトル行右端に警告アイコンのみ表示（テキストラベルなし）。プロジェクトロード時 (`state.kind === "loaded"` に遷移したとき) は「リンク切れが N 件あります」を warning Toast で 1 回通知し、同一 `loadedPath` 内では再発火しない。リンク切れ行の navigate ボタンは描画されず、クリック不可。 | リンクを削除するか、参照先ファイルを作成 |
| 循環参照 | 親子関係が循環している | 詳細（全画面 2 ペイン）にエラーバナー「循環参照が検出されました」 | `parent` フィールドを修正 |
